# GenesisAI CLI 用户指南

## 1. 产品定位

GenesisAI 在默认或指定工作区中运行一个持续的单 Agent Session。它可以读取和修改代码、执行测试、查看 Git 状态与差异、整理文件、检索公开网络、维护项目工作记忆、加载 Skills，并创建基础办公文档。

它使用 OpenAI 兼容模型协议。默认模型配置随包安装，也可通过终端配置或 `--config <文件路径>` 选择模型。密钥优先取环境变量和 `.env`，没有时使用终端保存的配置。内置 SQLite，无需部署数据库服务。

## 2. 安装与启动

```powershell
cd D:\path\to\your-project
python -m venv .venv
.venv\Scripts\python.exe -m pip install "D:\path\to\GenesisAI[office]"
.venv\Scripts\genesis.exe --workspace .
```

开发仓库内可直接运行：

```powershell
.venv\Scripts\python.exe cli.py
```

Linux 使用对应的 `.venv/bin/python` 和 `.venv/bin/genesis`。V1 的主要实际验收平台是 Windows。

### 阿里云 Token Plan

在工作区或项目根目录的 `.env` 中填写套餐专属密钥。

```dotenv
QWEN_TOKEN_PLAN=sk-sp-替换为你的套餐密钥
```

重启后运行 `genesis --auth`，或在会话中输入 `/auth`，选择「阿里云 Token Plan」。默认选择 `qwen3.8-flash`，菜单提供 `qwen3.8-max`、`auto` 和自定义模型 ID。`/model` 可在当前提供商内切换模型。已有 ENV 密钥时跳过终端密钥输入，ENV 为空时使用终端保存或输入的密钥。

通过 `--config` 使用 YAML 时，填写 `provider: qwen_token_plan` 与对应 `model`。该提供商默认访问 `https://token-plan.maas.qianwenaiapi.com/compatible-mode/v1`，支持用 `QWEN_TOKEN_PLAN_BASE_URL` 覆盖未显式指定的地址。终端配置保存的地址优先于地址环境变量。

套餐适用于交互式编程和智能体工具，具体模型及使用范围见[官方接入文档](https://platform.qianwenai.com/docs/token-plan/personal/token-plan-personal-quickstart)。

## 3. 工作区与状态

未传 `--workspace` 时，新会话使用 `~/.genesisai/workspace`，首次启动自动创建。设置 `GENESISAI_HOME` 后，新会话使用该目录下的 `workspace`。也可用 `--workspace "E:\my-project"` 指定其他目录。相对任务文件路径以当前工作区解释，默认输出到该目录。以下是默认布局。

```text
~/.genesisai/workspace/
~/.genesisai/state/genesis.sqlite3
~/.genesisai/assets/images/
~/.genesisai/projects/<project_id>/
~/.genesisai/capabilities/
~/.genesisai/logs/
~/.genesisai/traces/
~/.genesisai/command_logs/
~/.genesisai/backups/
```

历史目录不可写时报告错误，不回退到应用或任务目录。`--session SESSION_ID` 从统一目录恢复当前格式的会话及原工作目录；同时指定的 `--workspace` 必须与原目录一致。不提供旧会话格式迁移。外挂 Tool、Skill、MCP 的草稿、测试及注册信息位于 `capabilities/`；Workflows 与 LSP 配置保存在 `projects/<project_id>/`。项目中只读取可选 `AGENTS.md`。`.env` 不允许作为普通资料读取。

## 4. 权限

新会话默认使用用户审批。用 `/permissions` 查看当前模式。

| 模式 | 本地只读 | 写入、运行命令、联网、MCP | 内置文件工具的路径 |
| --- | --- | --- | --- |
| `/permissions user` | 直接执行 | 匹配有效范围授权时执行，否则单独审批 | 已授权路径 |
| `/permissions auto` | 直接执行 | 自动执行 | 允许工作区外的宿主文件 |

用 `/approve` 批准当前展示的调用，或用 `/reject` 拒绝。已有待确认调用在切换模式后仍需处理。单次确认绑定工具参数和资源预览，没有固定等待过期时间；参数、内容或来源变化会重新展示。模型对话、会话日志和已启用的项目工作记录随任务运行。MCP 服务按需启动，向声明为只读的服务发送参数也需要对外调用权限。

用 `--permissions user` 或 `--permissions auto` 指定启动模式。恢复会话时沿用保存的模式，未设置时采用用户审批，`/new` 默认用户审批。自动审批下命令以当前系统账号执行，内置文件工具支持宿主绝对路径，仍会检查工具参数和目标冲突，并保护 .env 密钥文件及当前应用状态目录。删除操作和外挂注册验收仍需明确确认。一次已批准的命令可能包含多个动作，并使用当前系统账号的权限。

用 `/authorize JSON` 创建会话或当前任务的范围授权，`/authorizations` 查看，`/revoke auth_...` 撤销。授权可限定工具集合、路径、域名、环境变量映射和命令前缀；任务授权在当前任务结束或被替换后失效。`/constraints JSON` 可显式调整当前任务的只读或禁网约束。具体语法和命令隔离边界见[范围授权与环境隔离](范围授权与环境隔离.md)。

## 5. Tool 与 Skill

`/tools` 按内置、外挂分组，逐项显示可用状态；`/capabilities` 同时列出 Tool、Skill、MCP 服务、草稿及测试报告。路由和已加载 Skill 推荐当前工具，完整目录可通过 `discover_tools` 分页查询和精确加载，实际定义受模型 Token 预算约束。回答或恢复过程中发现仍需行动时可继续调用工具。外挂有个人（user）和项目（project）作用域；同名冲突显式报错，不覆盖内置或其他已启用能力。

工具有共同的执行时限和输出预算。审批等待单独计时，批准后重新校验预览。只读工具超时会报告 `tool_timeout`。写入或对外产生副作用的工具一旦开始执行，超时后标记 `unknown_execution` 并中断任务，请先核对结果。模型收到的文本超过工具预算时，会看到预览和 `ref`，可用 `memory_read` 分页读取完整返回值。图片沿用独立的图片预算。

`attempt_completion` 提交一份待验收的最终回答，验收与直接回复共用同一流程。涉及代码改动、测试、来源或产物时，运行时会按任务要求检查后再结束。

常用命令如下。

```text
/skills list
/skills search bug
/skills show bug_fix
/skills load bug_fix run
/skills unload bug_fix
```

Skill 是低优先级工作流说明；加载时将声明的依赖加入工具选择范围，不执行脚本、不扩大权限。

### 创建、测试与注册外挂

```text
/create_tool 将输入整数翻倍，处理非法输入，并给出测试
/create_skill 按固定格式整理项目检查结果
/create_mcp 连接指定的服务，验证发现和实际调用
/capabilities
/capabilities protocol
```

创建入口让 Agent 读取协议、逐文件编写实现与夹具，以 path 引用导入草稿，冻结当前版本后调用真实测试。创建只需 name/description，定义、文件和用例可通过增量修订逐步完善。创建先产生草稿，草稿不会进入日常工具或 Skill 目录。Tool 的 runner 可选 python 或 command，在子进程中读取 stdin JSON，将结果 JSON 值写入 GENESISAI_RESULT_PATH 文件；stdout/stderr 仅用于日志，结果和日志以不可变引用分页读取；Skill 用当前模型在独立会话执行任务，检查回答和真实文件产物；MCP 通过明确的 stdio 或 streamable_http 传输连接服务、发现能力并进行实际调用。远程定义包含 transport=streamable_http、url、read_only 和可选 headers_from 环境变量引用；协议版本为 2026-07-28，通过 server/discover 发现能力，每请求携带协议元信息；不保留旧初始化握手、会话头及 GET 恢复路径。结果不明时不自动重发调用。HTTP 支持参数头映射及 Unicode 安全编码，畸形参数头声明只排除对应工具。

测试报告绑定修订号、内容摘要和报告编号。模型生成测试用例，因此仍需用户判断覆盖范围和实际效果。通过后可继续试用、要求调整，满意时才批准 `register_capability`。即使 `/permissions auto` 也会停下来等待明确验收。注册后即可按需发现、执行，并在重启后复用。修改草稿不替换已注册版本；新修订须测试和验收后才能生效。对同一修订重新测试会使旧验收失效，须重新确认最新报告。

自行编写能力时，先通过 `/capabilities protocol` 查看三类包的完整字段和示例，保存为工作区内的 JSON 文件。可直接运行以下命令，无需让模型代写实现。Skill 的测试和试用仍需要模型。

```text
/capabilities import "my capability.json"
/capabilities show cap_实际编号
/capabilities freeze cap_实际编号
/capabilities test cap_实际编号
/capabilities try cap_实际编号 trial.json
/capabilities revise cap_实际编号 1 "changes.json"
/capabilities register cap_实际编号
/capabilities export cap_实际编号 exported.json
/capabilities disable cap_实际编号
```

`trial.json` 包含 `input` 对象和可选的 `fixtures` 文件引用映射，如 `{"data.bin":{"path":"fixtures/data.bin"}}`，支持二进制。试用单独保留结果，不替代全部测试。`revise` 的数字为预期修订号；增量文件包含 description、definition、files、directory、tests、remove_tests 中需修改的字段。definition 按字段合并（null 移除字段），files 按路径更新，tests 按 name 更新；files 的 null 仅移除草稿引用，不删除原文件或旧版本。修订后重新 freeze/test。导出生成清单及独立 .assets 目录，不覆盖已有文件。停用保留草稿、历史版本与报告，移除日常目录中的对应能力。

能力实现、二进制资产和夹具按 SHA-256 存储，清单只包含引用；整包不再有 2 MB、100 文件、20 用例限制，至少需要一个成功用例。默认单文件导入 512 MiB、资产库 5 GiB，可通过应用目录 capabilities/limits.json 的 import_max_bytes/storage_max_bytes 配置。配额不足时报错，不自动删除资产；测试支持预期结果 JSON Schema 或错误码。外挂 Tool 的 timeout_seconds 是可选执行总时限，省略时不限总时长。MCP 使用 definition.request_timeouts：connect 默认30秒、first_response 默认300秒、idle 默认300秒、total 默认null；测试、目录发现和正式调用使用同一配置。总时限不再由前台响应窗口决定。MCP 只有 token 匹配且数值递增的进度通知才会延长空闲等待，心跳和重复进度不延长。HTTP 底层使用可取消的异步连接；stdio 超时或取消会关闭本地进程树。两种传输均不自动重发不确定的请求。测试和试用通过独立作业运行，前台短等后可用同一作业 ID 收取结果。Skill 的轮次、工具数、Token 和总时长通过试用输入 budget 显式设置，默认不限。测试和试用默认使用独立目录，生成程序不接收宿主 Session 或注册服务对象；这些是进程和目录隔离，不是操作系统安全沙盒。生成程序仍使用当前系统账号，MCP 测试仍可能访问真实外部服务。

Skill 测试返回 `artifacts` 产物清单，按相对路径记录 `id`、`sha256`、`size`、`kind` 和可验证的格式信息；不再把文本正文嵌入 `files`。大文本与二进制均保存为不可变资产，原测试文件后续变化不会改变验收快照。`read_capability_artifact` 可按引用读取元数据，或以 `mode=text`（字符偏移）／`base64`（字节偏移）分页至末尾；引用沿用能力的个人／项目作用域，读取时核对哈希。JSON Schema 可检查文本或二进制的实际哈希和大小，以及图片的格式、宽高；格式检查失败会保留字节并返回 `inspection_error`。采集受资产导入与存储配额约束，超额明确失败并保留已有产物，不静默漏掉大文件。

旧用户／项目 Skill 目录和 `mcp.json` 不再自动加载，也不自动转换。原文件保留；需要使用的能力应按当前协议创建草稿、测试并验收。内置能力和当前格式会话恢复仍正常工作。

## 6. 项目工作记忆

项目任务、版本化知识与代码结构索引统一保存在应用目录。用户项目不会创建 `agent_docs/` 或 `.genesis/`。

任务保存完整目标、每轮用户补充、约束来源、计划节点和交接。状态询问不会结束已有执行目标，短句续接不会清空失败测试；只有对应修改通过实际验证后才解除待验证状态。已完成的任务保持结束，后续文件变化不会自动重开旧目标。当前任务记录格式为 schema_version=2；不自动迁移旧格式，遇到旧格式会明确报错并保留原记录。

模型通过 `plan(operation="read")` 分页读取计划，也可指定 section 为 objective、instructions、constraints 或 handoff 获取完整记录。`plan(operation="update", expected_revision=..., upsert=[...])` 按稳定节点 ID 增量修改，节点分 phase、step 和 acceptance；不存在固定步骤数量上限。完成项需引用实际成功工具调用的 evidence_calls，requires_verification=true 的验收项还需当前修改版本的实际验证通过。测试通过不会自动完成其他计划项。

```text
/project
/project rebuild
/memory list
/memory search 关键词
/memory read 引用
/memory diagnostic
/memory export 新文件.md
```

知识修改使用 `/memory write JSON路径`，文件根对象为 `entries` 数组，每项包含 title、kind 及 body 或 body_ref；sources 记录证据。修改已有条目还需要 ref、expected_revision。body_ref 可按 file_、event_（view=content）、output_ 或 note_ 的不可变引用及字符范围读取；note_ 还绑定 revision。整个批次原子提交，审批绑定冻结正文与来源版本，冲突不提交部分知识。`/memory delete 引用 版本` 先显示预览，追加 `--confirm` 才删除。`/memory backup 新文件.sqlite3` 备份数据库；完整备份还需复制 assets 与需要保留的日志。

`/memory rebuild` 和 `/project rebuild` 提交后台维护，分别重建完整派生记忆或项目索引，保留原文。用 `/memory jobs [编号] [偏移]` 查看状态、`/memory cancel 编号` 取消；模型可通过 `memory_maintenance` 提交、分页查询、等待最多30秒或取消。维护不再依赖模型轮次推进，共享全局执行槽位，另有默认1个的维护池，可在状态目录 `maintenance/limits.json` 配置 `max_concurrent`。关闭宿主会重排中断的派生工作，用户明确取消的作业保持取消。

项目目录 `projects/<project_id>/index.json` 可配置 `git_timeout_seconds`（默认 null，不限定 Git 总时长）、`cache_seconds`（默认15秒）、`progress_batch`（默认128）和 `exclude_directories`。显式重建跳过路径缓存，变更文件先同步标记旧证据失效再异步扫描；扫描期间文件再变更时不会以旧结果覆盖新状态。扫描有进度和取消检查，未完成扫描不会删除未遍历的旧索引。

默认上下文窗口为 400K，输入预算在预留输出和安全余量后为 394880 tokens。模型平时携带近期历史与项目目录，较早原文按需查阅；`/budget` 和 `/memory diagnostic` 展示实际组装信息。详见[记忆系统架构](记忆系统架构.md)。

## 7. 代码与文件任务

代码修改采用行号读取、原文件 SHA-256 和 unified diff。补丁应用前若文件已变化会拒绝覆盖。`run_commands` 自动识别常见 Python、Node 和 Rust 测试入口，也可显式传入命令数组。Git 状态和差异通过 `run_commands` 的只读命令查看。

`/diff` 查看当前运行记录的文件操作、路径和变更前后哈希。

### 文字与图片

先用 `/model` 选择标记为“支持图片”的模型。已接入 Qwen 按量端点的 `qwen3-vl-plus`、`qwen3-vl-flash`、`qwen3.8-max`、`qwen3.8-flash`、`qwen3.7-plus`，以及 Token Plan 端点的 `qwen3.8-max`、`qwen3.8-flash`、`qwen3.7-plus`。其他模型或自定义端点的图片能力未确认时会明确拒绝图片请求，文字对话仍可使用。不会自动切换提供商、端点或模型。

```text
/attach "E:\PROJECT\GenesisAI\src\genesisai\app\assets\pet\spritesheet.webp"
请描述这张图片里的角色和排列方式
```

可以重复 `/attach` 添加多图；`/attachments` 查看待发图片，`/attachments clear` 移除待发附件，`/send` 仅发送图片。附件在成功登记本轮消息后移出草稿，登记前失败会保留。路径使用现有授权范围；工作区外图片需符合当前文件访问权限。选择附件时会检查和冻结像素，排队期间原文件变化不会更换已选择的图片。切换会话或退出会丢弃未发送的内存附件，原文件保留。

单次执行支持重复 `--image`，纯图片请求可省略 `--prompt`：

```powershell
genesis --workspace E:\PROJECT\GenesisAI --image E:\PROJECT\GenesisAI\src\genesisai\app\assets\pet\spritesheet.webp --prompt "描述图中的角色"
```

本期支持静态 PNG、JPEG、WebP，不接入视频、音频、动画图片、剪贴板截图或远程图片 URL 下载。默认不限制图片张数（`max_images: null`）；单张原图及 PNG 视图各不超过 10 MiB、解码不超过 3200 万像素。原图完整保存，默认预览长边为 1536。待发送原图与预览总配额为 128 MiB（`max_pending_image_bytes`），单次模型请求图片合计预算为 12 MiB（`max_request_image_bytes`），并受上下文视觉 Token 预算约束。请求优先发送最新工具读取的图片，再发送当前用户图片；暂未加载的图片显示引用和明确提示，可分批读取。显式设置 `max_images` 可适配供应商数量限制，超出部分仍保留原图与引用。`/budget` 展示实际发送的图片数量、估算 Token 与字节。

模型可通过 `read_image(path=...)` 查看授权图片，用 `read_image(image_ref=...)` 重读历史图片。两者均支持 `crop={x,y,width,height}` 和 `max_side`；坐标以按 EXIF 校正方向后的完整原图为准，即使引用本身是裁剪视图也如此。`max_side` 可超过默认 1536，但不会放大原图，仍受字节与解码预算约束。返回值包含原图宽高、哈希和裁剪范围。MCP 的 text/image 内容走同一链路。快照位于状态根目录的 `assets/images/`，原图位于其中的 `originals/`；对话与日志保存引用或载荷摘要，不内嵌 Base64。工作上下文可暂时卸载像素，原对话及快照保留；切换容量后会重新计算保留消息中的图片预算。同一工作区的其他会话也能按精确引用读取。快照损坏或缺失时明确报错，不猜测视觉内容。

图片能力依据：[千问视觉模型说明](https://platform.qianwenai.com/docs/developer-guides/getting-started/text-generation-models)、[Token Plan 视觉支持](https://platform.qianwenai.com/docs/token-plan/best-practices/add-vision-skill)。

## 8. 网络研究

网络研究遵守 `query → candidate → fetch → Evidence → answer`。搜索结果摘要只是候选，只有抓取并登记过的正文才能成为 `src_` 引用。相同 Session 中的后续追问会优先复用上一轮 Evidence，避免重新搜索和反复授权。

## 9. 办公文件

安装 `genesisai[office]` 后可按需启用：

| 格式 | V1 能力 |
| --- | --- |
| DOCX | 段落、表格、页眉页脚读取；基础创建；文字替换式有限编辑 |
| XLSX | 工作表、值、公式和合并区域读取；基础创建；指定单元格修改 |
| PPTX | 幻灯片文字、备注和对象数量读取；标题与项目符号基础创建 |

## 10. 终端操作、恢复与诊断

交互终端使用多行输入区。Enter 发送，Alt+Enter 或 Ctrl+J 换行，方向键编辑和浏览输入历史。粘贴多行内容后按 Enter 提交。输入 `/` 即显示命令候选，支持命令名和中文说明搜索。↑↓ 选择，Enter 执行，Tab 补全，Esc 收起候选。`/help` 打开同一命令选择器，Esc 返回任务输入。

普通启动显示当前工作区和最近五段有内容的对话。输入第一条消息才新建会话；空输入框按 ↑ 选择最近对话，`/sessions` 查看全部工作区。选中会话或使用 `--session` 后直接显示最近三轮问答，`/history` 显示全文。打开历史无需模型凭据；发送任务时按需配置模型，会话上下文和相关工具结果会随请求发送给所选提供商。首次明确执行开发任务时才提示初始化项目记忆。用 `/new` 回到首页，或用 `/workspace 路径` 切换工作区。完整目录与运行信息在 `/status` 中查看。执行过程显示文件操作与命令结果，`/details` 展开或收起工具输出，`/logs` 提供完整日志路径。运行时 Ctrl+C 停止任务，空闲输入时 Ctrl+C 清空草稿，再按一次退出。

项目记录初始化和待确认操作使用方向键选择。Esc 离开操作确认菜单后，可输入 `/approve`、`/reject`、`/cancel` 或 `/exit`。非交互输入使用普通文本和序号菜单。

交互终端中，任务运行时仍可编辑输入。此时按 Enter 提交的普通消息按顺序排队，轮到它时才进入模型上下文。当前回答保存为成功后，队首自动开始。等待工具授权时，队列也等待。取消、失败、部分完成或到达预算上限后，使用 `/queue resume` 继续。用 `/status` 查看当前阶段，`/queue` 查看队列，`/queue clear` 移除所有尚未开始的消息。切换会话前需要处理队列。退出会丢弃内存中的队列，已执行的任务仍保存在原会话。

输入 `/cancel` 可中止模型等待或受控命令及其子进程。已经启动的命令可能留下文件修改，取消结果会保留这条信息。其他已开始的同步工具会在返回后处理取消。命令输出较快时，终端合并显示并提示省略。使用 `/logs` 查看完整的脱敏输出。运行中 Ctrl+C 先清空草稿，空输入框按 Ctrl+C 请求取消。

如果队首消息在新一轮保存前启动失败，该消息会回到队首。处理错误后可用 `/queue resume` 重试。已经登记的新一轮执行失败时，继续队列会从下一项开始。

- `/compact` 压缩历史工作上下文并保存会话检查点；原始对话和日志保留。待确认工具须先处理，短上下文可能无需压缩。自动压缩按单次请求容量触发，累计 Token 仅统计用量，不再按 75% 强制结束任务。`/budget` 分别显示两者；容量与摘要策略通过模型配置的 `context` 设置，详见 [上下文预算与压缩续跑](问题及解决清单/004-上下文预算与压缩续跑.md)；
- 输入 `/` 选择 `/sessions` 恢复历史聊天，也可直接输入 `/sessions`。选择后使用该会话的原工作区继续。
- `genesis --seconds 1800 --request-idle-timeout 120 --max-rounds 60 --max-tools 180 --token-budget 120000` 显式设置任务时长、模型流空闲时限、模型轮次、工具次数和累计 Token 预算。任务时长、轮次、工具次数和 Token 默认不限。`/budget` 显示实际配置，后台作业轮询不计入工具次数预算。摘要调用单独记账并受剩余总时限约束。每 20 轮记录进度检查点；恢复同一运行不会重置消耗，用户新输入会建立新 Run。
- 超长粘贴不会再按“字符数超过3倍Token预算”拒绝。完整用户消息先保存到会话库，单次上下文放不下时显示明确的首尾预览、未载入区间和精确引用；通过 `memory_read(ref, view="content", offset, limit)` 按字符读至末尾。任务目标仍完整保存，可用 `plan(operation="read", section="objective", offset, max_chars)` 读取。模型切换或预算变大时可重新加载原文；上下文溢出恢复只缩小请求中的预览，不修改原文。预览不代表全部内容已经审阅。
- `memory_read` 默认根据模型输入容量、实际用量校准和最近请求剩余空间分配页大小，单页最多20万原文字符；显式 `limit` 是本页字符上限。返回 `total_chars` 与实际 `next_offset`，沿游标可读至末尾，不按请求的 limit 猜下一页位置。引号、反斜杠和控制字符的 JSON 转义也计入预算；大页不再被旧的24000字符展示上限再次包装为归档预览。
- 模型 YAML 和用户配置中的 `request_timeouts` 分别设置 `connect`（连接及连接池等待，默认 30 秒）、`first_token`（首个有效输出，默认 300 秒）、`idle`（后续有效输出间隔及发送空闲，默认 300 秒）、`total`（整次请求，默认 `null` 不限）。正文、推理和工具参数片段算有效输出，心跳与空角色片段不算。非流式调用的首个有效输出是完整响应。底层异步等待会在到期或取消时中断并关闭连接；SDK 不额外重试，由宿主统一管理恢复。
- 终端分别用 `--request-connect-timeout`、`--request-first-token-timeout`、`--request-idle-timeout`、`--request-total-timeout` 覆盖对应配置；`--request-total-timeout none` 清除模型配置的总时限。其余项保持模型配置。切换模型会载入新配置并保留显式终端覆盖。任务及供应商重试的剩余预算始终约束请求总时长；这些本地参数不会作为生成字段发送给模型。Skill 试用输入 `budget.request_timeouts` 使用同一结构。
- 模型配置的 `retry` 控制临时连接错误、请求超时、限流和服务端错误的恢复：`budget_seconds` 默认 600（0 禁止重试），`initial_delay_seconds` 默认 1，`max_delay_seconds` 默认 30，`jitter_ratio` 默认 0.2。该预算从首次临时错误后开始，独立于工具进展和上下文压缩；退避遵守服务端 `Retry-After`，超出剩余预算时保存进度并明确停止。等待期间可以取消。用户配置、模型 YAML 和独立 Skill 宿主使用同一设置。
- `/resume` 恢复可安全继续的运行，`started/unknown` 副作用不会自动重放；

出现失败时使用 `/status` 查看状态、`/trace` 查看执行摘要、`/logs` 获取完整日志路径。待确认状态使用 `/approve` 或 `/reject`。

项目文件和应用任务状态更新后可以继续同一会话。应用保留历史哈希，将已变化或删除的文件快照标为失效，并提示模型按需重新读取；旧来源不能作为当前文件内容的证据。批准执行的修改和测试与直接执行采用相同的状态更新。普通问答和创作正文随模型生成逐段显示。工具调用在参数接收完整后执行，需要核实来源或验收的回答在检查后展示。流式正文输出前停止加载动画；若最终状态与模型正文不一致，界面额外显示运行时的判定原因。

## 编码工具

- `search_codebase` 的 `content` 模式返回路径、从 1 开始的行列、匹配片段和前后文。用 `context_lines` 调整上下文宽度。先按 `next_offset` 读取本批命中，再以 `next_file_offset` 作为 `file_offset` 并把 `offset` 归零，继续扫描下一批文件。Office 和 PDF 的行号对应提取后的文字。
- `context_lines` 最大 40；`output_mode=files/count` 可返回命中文件或匹配行数，`max_output_chars` 限制输出量。`mode=index` 支持 `next_cursor` 分页，文件集合或元数据变化后旧游标失效，需重新开始。索引明确标记单文件截断和解析失败；Python 使用现有项目索引的 AST 解析，JS/TS 当前为正则覆盖，不代表完整语义分析。
- `read_files.files` 可为各文件指定独立行范围或字符偏移，不能与 `path/paths` 混用。默认整次正文上限为 24000 字符，使用 `remaining_requests` 作为下一次的 `files` 继续读取。普通源码字符分页可读取 20 万字符以后的内容；Office/PDF 仍受文档提取上限约束。
- `discover_tools` 默认返回 20 个候选，每页最多 100，可用 offset 分页及 provider/category/source 筛选；完整定义的实际加载量受当前模型 Token 预算约束，`available_next_round` 表示下轮可用工具。`activate=false` 只查看候选，需要时可按精确工具名再次发现。工具发现、任务路由和 Skill 均不扩大权限；本地开发可按需使用网页工具，用户禁网或只读要求仍约束实际执行。
- 后台命令返回 `job_id` 后，用 `read_job(job_id=..., wait_seconds=30, output=true)` 有界等待并分页读取输出。测试作业完成后会返回摘要，旧测试不能验证启动后修改的文件；恢复时若作业所有者不可用，不自动重放命令。
- `editor` 的 `replace` 接受 `path`、`old_text`、`new_text`，旧文字须恰好匹配一次。`patch` 支持单个文件，也支持 `patches` 数组。批量操作先逐个预检，确认时展示每个文件的 diff。执行过程中发生冲突时，结果会列出已修改、失败和待处理的文件，已写入的文件保留备份。
- `run_commands` 由独立作业宿主执行，前台等待期间显示实时输出；超过 5 秒响应窗口自动返回 job_id，background=true 立即返回。timeout_seconds 是可选总时限，默认不限制作业寿命。read_job 支持等待、目录分页和 UTF-8 字节偏移输出读取；stop_job 取消作业及其进程树。会话关闭后作业继续运行，重新打开可接续读取；取消当前运行或权限降级会停止对应作业。并发默认 4、超额排队，日志按 1MiB 分段持久化，默认单作业输出配额 128MiB；会话日志记录作业身份和完整输出引用，可按引用或 read_job 读取尾部。用户状态目录 jobs/limits.json 可配置 max_concurrent、log_max_bytes 和 result_max_bytes（完整结构化结果配额，默认 128MiB）。配额耗尽明确报告失败，保留已产生输出；宿主由操作系统租约确认存活；心跳延迟只标记 heartbeat_stale，租约丢失才标记 unknown，禁止猜测成功或自动重放。
- 外挂 Tool、能力测试/试用、MCP 调用和资源读取也使用独立作业宿主；超过前台窗口时先返回作业引用。使用 read_job 读取实际结果，确认测试通过后才能注册。测试套件逐例保存进度，未知结果不得当作通过。
- `read_files`、`list_files`、Office 和声明 `execution='job'` 的文件工具使用独立作业，前台最多等待5秒，随后用 `read_job` 收取。原30秒前台准备时限不再限定后台操作寿命；工具可另设 `execution_timeout_seconds`。排队后重新核对审批资源，来源、产物和修改记录随结果导入当前会话，不覆盖其间新增的对话状态。重复收取不重复产生修改观察；原文件变更或移走仍可收取历史结果，并标明来源已过期。授权范围变化会阻止读取旧授权产生的结果。结果发布失败、执行结果未知时保留待核对作业，不自动重放；失联作业仍可发送停止请求。
- 模型调用 `ask_user` 时，会话进入 `awaiting_input`。直接输入文字、选项编号或 `/answer 文字` 即可继续同一任务。可保存退出，在原会话继续作答。`/cancel` 结束任务。

### 项目语言服务和 MCP 资源

启动 MCP 子进程时，GenesisAI 会过滤父进程中的敏感环境变量。服务需要凭据时，在能力包 `definition.env_from` 中声明服务变量名到宿主变量名的映射，例如 `{"SERVICE_TOKEN":"MY_SERVICE_TOKEN"}`；包中不保存密钥值。缺少变量时明确报错，实际值变化后会重建连接。`definition.read_only` 接受 JSON 布尔值 `true` 或 `false`。

LSP 配置放在应用管理的项目目录 `%USERPROFILE%\.genesisai\projects\<project_id>\`。用户项目只需保留自己的源码和配置。用户权限模式会在启动外部服务前展示命令。

`lsp.json` 按文件后缀选择语言服务。例如，安装 `python-lsp-server`（可选依赖 `genesisai[lsp]`）后，可使用以下配置。`pylsp` 须能从应用的 PATH 启动，也可替换为绝对路径。

~~~json
{"servers": {".py": {"language": "python", "command": ["pylsp"]}}}
~~~

`lsp_query` 支持 definition、references、pull diagnostics 和 capabilities，提交后返回 query_id；`read_lsp_result` 分页取回完整结果，`cancel_lsp_query` 取消排队或运行查询。输入和输出的行列均从1开始，列按 UTF-16 代码单元计数。服务连接在宿主生命周期内复用，可配置授权的多个 workspace_roots；返回位置仍逐页核验范围和来源版本。查询共享 `jobs/limits.json` 的全局并发槽位，同时受 LSP 自身并发配置约束；排队保持心跳，不计入启动或查询时限。关闭宿主、取消运行或权限降级会取消相关查询；宿主失联后的未知查询不自动重放。rename、codeAction、formatting 和 push diagnostics 尚未提供。

已注册 MCP 服务声明 `resources` 能力后，调用 `connect_mcp` 即可发现 `list_mcp_resources`、`list_mcp_resource_templates` 和 `read_mcp_resource`。列表返回的 `nextCursor` 可作为下一次调用的 `cursor`。读取时向对应服务器传入完整 URI，返回文字或经应用图片校验后的图片引用。外部工具按服务器提供的 JSON Schema 校验嵌套参数、枚举和本地引用。服务器报告 `isError` 时，该调用以失败写入账本。


## 交互式命令作业

需要向程序持续输入时，启动 run_commands 时明确设置 interaction.mode 为 pipe 或 pty。pipe 提供标准输入管道；pty 提供真实终端，支持需要终端环境的程序。Windows 的 pty 需要安装可选依赖 genesisai[terminal]。未指定 interaction 的命令使用关闭的标准输入。

长命令返回 job_id 后，用 read_job(job_id, output=true) 读取输出。write_job_input 支持 write、close 和 resize：write 接受 text 或 secret_from_env 二选一，append_newline=true 按当前模式追加行结束符；close 只适用于管道；resize 只适用于 PTY，需给出 rows 和 columns。

每次输入返回 input_id。accepted 表示已进入发送队列，sent 才表示发送已完成。使用 read_job(job_id, input_id) 查看回执。unknown 表示发送结果未确认，应核对输出和回执，不要重发同一输入。

终端运行中和空闲时均可手动输入，例如：

~~~text
/job-input {"job_id":"job_...","action":"write","text":"yes","append_newline":true}
/job-input {"job_id":"job_...","action":"write","secret_from_env":"MY_DEV_TOKEN","append_newline":true}
/job-input {"job_id":"job_...","action":"close"}
/job-input {"job_id":"job_...","action":"resize","rows":35,"columns":100}
~~~

该命令只能控制当前会话所属且仍获授权的交互作业。它不会改写正在运行的会话状态，命令原文不会保留在 CLI 日志或输入历史中。发送到程序的环境变量密钥会先加入输出脱敏集合。


内网读取使用独立的 fetch_private_resource(url,address_ranges)，即使 auto 模式也需要具体确认或有效的 /authorize 主机与 CIDR 授权。每跳域名、全部解析地址和固定连接 IP 均受校验，公共 fetch_web_content 不放行私网。内网缓存绑定有效授权范围，撤销后不能通过再次调用读取缓存。下载资源包含 raw_source 的长度、哈希和媒体类型；pdf_ocr 可选 path 或当前会话的 source_ref，二者互斥，下载 PDF 经完整性检查后才进入本地 OCR 作业。

MCP 目录、资源 URI 和游标不再被旧数量/字符上限截断；重复游标和32MiB单响应保护仍生效。结构化结果任意层的 url/uri/href/links 字段及 resource_link 内容块可以登记候选并保留字段路径，普通指令文字中的 URL 不被推断为显式链接。链接发现不等于网络访问授权。客户端当前声明空的可选能力集，不伪装支持 elicitation、sampling、roots 或订阅。


### 动态网页、测试续跑与写入协调

- `render_web_page` 是独立的显式 Chromium 工具。安装 `genesisai[browser]` 后运行 `python -m playwright install chromium`。默认只读取初始主机，可用 `resource_domains` 声明额外资源主机；这些范围还必须与当前授权相交。浏览器不复用用户登录状态，只执行 GET，禁用 Service Worker、WebSocket 和表单提交。HTTP 读取全部经公网 DNS 固定连接客户端；初始跳转由该客户端处理，动态文档跳转重定向会显式阻止。子资源重定向的浏览器 URL 保持原请求 URL，可能影响依赖响应 URL 的页面。默认256个浏览器请求、64MiB资源预算，可调 `max_requests/max_total_bytes`；统一使用 `network_limits` 总时限。等待选择器 `wait_for` 或 `settle_seconds` 后保存完整 DOM、正文及来源；快照始终标明不是未来全部页面状态的完整保证。
- `test_capability` 按用例保存检查点，`read_job` 的 progress 提供 `report_id`。套件停止后，可用同一 id/revision/digest 和 `resume_report_id` 续跑。已完成用例不重复执行；结果不明的用例必须显式传 `reconcile={"case":"用例名","action":"retry"}` 或 `mark_failed`。retry 表示已核对并决定重新执行，原记录和尝试目录保留；mark_failed 不会产生通过报告。运行中套件有操作系统独占锁，不能并发续跑。test/try 的 `timeout_seconds` 是可选的独立总时限，默认不设总时长上限。
- `editor` 与其他异步文件工具在执行槽之外等待冲突写入，范围覆盖相同路径及其父子目录。进入执行后重新准备并校验前态，防止旧补丁覆盖新内容。命令默认按 cwd 协调，可通过 `write_paths` 声明更小的工作区范围，纯只读命令或服务显式传 `[]`。声明用于协调，不是操作系统沙箱，无法推断程序在声明范围之外的写入。外部编辑器仍可能在最终文件替换的瞬间竞争，需配合哈希检查与备份。
- 文档修改不再强制触发项目测试。代码按验收选择具体测试、构建或静态检查；显式构建/静态命令通过 `run_commands(verification="build"|"static")` 和同一作业的 `read_job` 记录真实结果。检查失败和过期验证仍会阻止把相应验收项标为完成。
