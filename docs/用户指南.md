# GenesisAI CLI 用户指南

## 1. 产品定位

GenesisAI 在默认或指定工作区中运行一个持续的单 Agent Session。它可以读取和修改代码、执行测试、查看 Git 状态与差异、整理文件、检索公开网络、维护项目工作记忆、加载 Skills，并创建基础办公文档。

它使用 OpenAI 兼容模型协议。模型可通过终端配置或 `config/model.yaml` 选择，密钥优先取环境变量和 `.env`，没有时使用终端保存的配置。不需要数据库。

## 2. 安装与启动

```powershell
cd D:\path\to\your-project
python -m venv .venv
.venv\Scripts\python.exe -m pip install "D:\path\to\GenesisAI[office]"
.venv\Scripts\genesis.exe --workspace .
```

开发仓库内可直接运行：

```powershell
.venv\Scripts\python.exe cli.py
```

Linux 使用对应的 `.venv/bin/python` 和 `.venv/bin/genesis`。V1 的主要实际验收平台是 Windows。

## 3. 工作区与状态

未传 `--workspace` 时，使用固定默认工作区 `~/GenesisAI/workspace`，首次启动自动创建；也可用 `--workspace "E:\my-project"` 指定其他目录。相对任务文件路径以当前工作区解释，默认输出到该目录。无论选择哪个工作区，应用历史均统一保存于默认工作区：

```text
~/GenesisAI/workspace/.genesis/sessions/
~/GenesisAI/workspace/.genesis/logs/
~/GenesisAI/workspace/.genesis/traces/
~/GenesisAI/workspace/.genesis/command_logs/
~/GenesisAI/workspace/.genesis/backups/
```

历史目录不可写时报告错误，不回退到应用或任务目录。`--session SESSION_ID` 从统一目录恢复当前格式的会话及原工作目录；同时指定的 `--workspace` 必须与原目录一致。不提供旧会话格式迁移。项目 Skills、Workflows 和 `agent_docs/` 随项目保存。`.env` 不允许作为普通资料读取。

## 4. 权限

读取授权工作区内的普通文件无需逐次确认。网络、写入和 Shell 各有独立的 Session 策略：

```text
/permissions
/permissions network allow
/permissions writes allow
/permissions shell allow
```

短命令 `/allow network|writes|shell` 会设置同样的 Session 授权，并在当前等待操作属于该类别时一并批准它。`/approve` 只批准冻结参数的一次调用。危险删除、覆盖、越界路径、命令解释器和 Git 写操作不能通过 Session 授权绕过。

## 5. Tool 与 Skill

`/tools` 展示启用和禁用两组工具；模型可使用全部已启用且满足平台和依赖条件的工具。Skill 来自内置、用户级和项目级三层，优先级为项目 > 用户 > 内置。常用命令：

```text
/skills list
/skills search bug
/skills show bug_fix
/skills load bug_fix
/skills unload bug_fix
```

Skill 只是低优先级工作流说明；加载 Skill 不执行脚本，也不会自动加载工具或扩大权限。

## 6. 项目工作记忆

项目工作记忆保存在任务工作区的 `agent_docs/`，记录项目概览、计划、进度、决策、已验证命令和验收结果。可在启动时使用 `--yes-agent-docs` 初始化，也可以进入会话后执行：

```text
/project
/project init
```

`agent_docs/` 不保存密钥、完整对话或原始命令日志；完整运行历史位于默认工作区的 `.genesis/`。

## 7. 代码与文件任务

代码修改采用行号读取、原文件 SHA-256 和 unified diff。补丁应用前若文件已变化会拒绝覆盖。`run_commands` 自动识别常见 Python、Node 和 Rust 测试入口，也可显式传入命令数组。Git 状态和差异通过 `run_commands` 的只读命令查看。

`/diff` 查看当前运行记录的文件操作、路径和变更前后哈希。

## 8. 网络研究

网络研究遵守 `query → candidate → fetch → Evidence → answer`。搜索结果摘要只是候选，只有抓取并登记过的正文才能成为 `src_` 引用。相同 Session 中的后续追问会优先复用上一轮 Evidence，避免重新搜索和反复授权。

## 9. 办公文件

安装 `genesisai[office]` 后可按需启用：

| 格式 | V1 能力 |
| --- | --- |
| DOCX | 段落、表格、页眉页脚读取；基础创建；文字替换式有限编辑 |
| XLSX | 工作表、值、公式和合并区域读取；基础创建；指定单元格修改 |
| PPTX | 幻灯片文字、备注和对象数量读取；标题与项目符号基础创建 |
| PDF | 页数、元数据和可提取文字读取；基础文本 PDF 创建 |

所有修改结果写为新产物，输入原件不覆盖。XLSX 公式只写入、不重新计算；扫描 PDF 没有 OCR；PPTX/PDF 不承诺任意原稿的高保真编辑。

## 10. 终端操作、恢复与诊断

交互终端使用多行输入区。Enter 发送，Alt+Enter 或 Ctrl+J 换行，方向键编辑和浏览输入历史。粘贴多行内容后按 Enter 提交。输入 `/` 即显示命令候选，支持命令名和中文说明搜索。↑↓ 选择，Enter 执行，Tab 补全，Esc 收起候选。`/help` 打开同一命令选择器，Esc 返回任务输入。

启动区显示模型、权限、工作区和会话状态，完整目录与运行信息在 `/status` 中查看。执行过程显示文件操作与命令结果，`/details` 展开或收起工具输出，`/logs` 提供完整日志路径。运行时 Ctrl+C 停止任务，空闲输入时 Ctrl+C 清空草稿，再按一次退出。

远程授权、项目记录初始化和待确认操作使用方向键选择。Esc 离开操作确认菜单后，可输入 `/approve`、`/reject`、`/cancel` 或 `/exit`。非交互输入使用普通文本和序号菜单。

- `/compact` 压缩历史工作上下文并保存会话检查点；原始对话和日志保留。待确认工具须先处理，短上下文可能无需压缩。自动压缩按单次请求容量触发，累计 Token 仅统计用量，不再按 75% 强制结束任务。`/budget` 分别显示两者；容量与摘要策略通过模型配置的 `context` 设置，详见 [上下文预算与压缩续跑](问题及解决清单/004-上下文预算与压缩续跑.md)；
- 输入 `/` 选择 `/sessions` 恢复历史聊天，也可直接输入 `/sessions`。选择后使用该会话的原工作区继续。
- `genesis --seconds 600 --request-timeout 120` 设置任务总时限和单次模型请求超时。默认分别为 300 秒和 60 秒，`/budget` 显示实际配置。
- `/resume` 恢复可安全继续的运行，`started/unknown` 副作用不会自动重放；

出现失败时使用 `/status` 查看状态、`/trace` 查看执行摘要、`/logs` 获取完整日志路径。待确认状态使用 `/approve`、`/reject` 或对应的 `/allow`。

项目文件和 `agent_docs` 更新后可以继续同一会话。应用保留历史哈希，将已变化或删除的文件快照标为失效，并提示模型按需重新读取；旧来源不能作为当前文件内容的证据。批准执行的修改和测试与直接执行采用相同的状态更新。流式正文输出前停止加载动画；若最终状态与模型正文不一致，界面额外显示运行时的判定原因。
