# GenesisAI CLI 用户指南

## 1. 产品定位

GenesisAI 在当前项目目录中运行一个持续的单 Agent Session。它可以读取和修改代码、执行测试、查看 Git 状态与差异、整理文件、检索公开网络、维护轻量 Memory、加载 Skills，并创建基础办公文档。

它只维护 OpenAI 兼容模型协议。当前模型由 `config/model.yaml` 选择，密钥来自环境变量或 `.env`。Memory 使用 JSON 索引与 Markdown 正文，不需要数据库。

## 2. 安装与启动

```powershell
cd D:\path\to\your-project
python -m venv .venv
.venv\Scripts\python.exe -m pip install "D:\path\to\GenesisAI[office]"
.venv\Scripts\genesis.exe --workspace .
```

开发仓库内可直接运行：

```powershell
.venv\Scripts\python.exe cli.py
```

Linux 使用对应的 `.venv/bin/python` 和 `.venv/bin/genesis`。V1 的主要实际验收平台是 Windows。

## 3. 工作区与状态

未传 `--workspace` 时，启动命令所在目录就是工作区。所有相对文件路径以工作区解释。常规 Session、Trace、日志和输出默认写入用户目录下按工作区路径生成的哈希目录；项目自身的 Memory 与 Skill 分别位于：

```text
<workspace>/.genesis/memory/
<workspace>/.genesis/skills/
```

若用户状态目录不可写，程序会回退到 `<workspace>/.genesis/`。`.env` 不允许作为普通资料读取。

## 4. 权限

读取授权工作区内的普通文件无需逐次确认。网络、写入和 Shell 各有独立的 Session 策略：

```text
/permissions
/permissions network allow
/permissions writes allow
/permissions shell allow
```

短命令 `/allow network|writes|shell` 会设置同样的 Session 授权，并在当前等待操作属于该类别时一并批准它。`/approve` 只批准冻结参数的一次调用。危险删除、覆盖、越界路径、命令解释器和 Git 写操作不能通过 Session 授权绕过。

## 5. Tool 与 Skill

`/tools` 展示 Core、Active、Available、Disabled 四种状态。Skill 来自内置、用户级和项目级三层，优先级为项目 > 用户 > 内置。常用命令：

```text
/skills list
/skills search bug
/skills show bug_fix
/skills load bug_fix
/skills unload bug_fix
```

Skill 只是低优先级工作流说明；加载 Skill 不执行脚本，也不会自动加载工具或扩大权限。

## 6. Memory

Memory 只保存短小、明确且可审查的信息。成功的测试命令会自动记录；稳定项目事实需要正式来源路径和哈希。用户可以查看、写入、失效、忘记或撤销：

```text
/memory list
/memory search pytest
/memory show mem_xxx
/memory add decision 标题|正文
/memory validate
/memory forget mem_xxx
/memory undo
```

来源文件变化后，验证状态会失效。Memory 不保存环境变量值、密钥、完整对话或项目全文。

## 7. 代码与文件任务

代码修改采用行号读取、原文件 SHA-256 和 unified diff。补丁应用前若文件已变化会拒绝覆盖。`test_run` 自动识别常见 Python、Node 和 Rust 测试入口，也可显式传入命令数组。Git 工具只提供 status、diff、log、show 和当前分支。

`/diff` 查看当前 Run 的 ChangeSet。`/undo` 先预览，`/undo apply` 执行；目标文件发生外部变化时撤销停止。

## 8. 网络研究

网络研究遵守 `query → candidate → fetch → Evidence → answer`。搜索结果摘要只是候选，只有抓取并登记过的正文才能成为 `src_` 引用。相同 Session 中的后续追问会优先复用上一轮 Evidence，避免重新搜索和反复授权。

## 9. 办公文件

安装 `genesisai[office]` 后可按需启用：

| 格式 | V1 能力 |
| --- | --- |
| DOCX | 段落、表格、页眉页脚读取；基础创建；文字替换式有限编辑 |
| XLSX | 工作表、值、公式和合并区域读取；基础创建；指定单元格修改 |
| PPTX | 幻灯片文字、备注和对象数量读取；标题与项目符号基础创建 |
| PDF | 页数、元数据和可提取文字读取；基础文本 PDF 创建 |

所有修改结果写为新产物，输入原件不覆盖。XLSX 公式只写入、不重新计算；扫描 PDF 没有 OCR；PPTX/PDF 不承诺任意原稿的高保真编辑。

## 10. 恢复、诊断与清理

- `/compact` 压缩早期上下文并保留目标、上一轮结果、来源和变更引用；
- `/resume` 恢复可安全继续的运行，`started/unknown` 副作用不会自动重放；
- `/doctor` 检查模型配置、目录、锁和可选依赖；
- `/clean` 只预览旧运行数据，`/clean run` 才执行清理；Memory、Skills、当前 Session 和未交付产物不会进入清理范围。

出现失败时先运行 `/status`、`/trace` 和 `/doctor`。待确认状态先使用 `/approve`、`/reject` 或对应的 `/allow`，不要把 `approve` 当作普通自然语言输入。
