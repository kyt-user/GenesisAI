# 完整输入输出日志

交互诊断统一写入追加式 JSONL；大工具结果、作业输出和图片保存在各自持久存储中，日志记录对应引用。完整内容应沿引用读取，不能把终端预览当成全部结果。

日志默认开启。打开已有会话或发送第一条消息后，输入 `/logs` 查看当前会话的准确路径：

```text
~/.genesisai/logs/<session_id>.jsonl
```

这是交互诊断日志的权威文件。每行一个 UTF-8 JSON 事件，已交付的事件正文不因终端预览限制截断；图片载荷保存为引用或摘要，不内嵌 Base64。事件写入后 flush + fsync；恢复会话继续追加原文件，`/new` 回到首页，下次提交任务时才创建新日志。时间戳使用带时区的 UTC；session_id、run_id、round_num、event_id 用于定位。

所有状态使用同一应用根目录，默认 `~/.genesisai/`，可由 `GENESISAI_HOME` 覆盖。`traces/` 保存 `/trace` 所用的轻量执行信息，`state/genesis.sqlite3` 保存可恢复会话，`jobs/<session_id>/<job_id>/` 保存独立作业状态、分段输出和结果。用户项目不再创建 `.genesis/` 状态目录；这些记录职责不同，不能相互替代。

## 覆盖范围

| 输入输出 | 事件 | 内容 |
| --- | --- | --- |
| 启动与会话 | `session_open` / `session_switch` / `session_close` | 工作区、CLI 参数（含 --prompt）、会话切换及结束状态 |
| 用户主循环输入 | `cli_input` | 普通输入及 /approve、/reject、/new、/auth 等命令；`/job-input` 仅记占位文本，密钥和 PDF 密码输入不记原文 |
| 开始一轮任务 | `user_input` / `run_start` | 普通输入正文及 input_event_id，用于关联新 run_id |
| 终端输出 | `cli_output` | Rich 实际渲染后的文本，包括结果、命令输出、报错和确认预览；在操作返回时保存 |
| 模型输入 | `model_input` | 每次尝试的完整系统提示、历史消息、工具定义、调用选项和模型名 |
| 提供商实际调用 | `provider_request` | OpenAI 兼容适配器交给 SDK 的完整参数，包括 generation / thinking / stream 默认值和 base_url；不记录 HTTP 认证头 |
| 提供商响应 | `provider_response` / `provider_stream_chunk` | SDK 解析后的完整响应对象或每个流式 chunk，包括服务端 ID、usage、reasoning_content 等 |
| 模型标准化输出 | `model_output` | content、reasoning、tool_calls 及其完整 arguments、usage、finish_reason |
| 流式输出 | `model_stream_chunk` | 每个正文 / reasoning 文本片段即时写入；中途失败仍保留已经到达的片段 |
| 模型失败 | `model_error` | 每次失败的错误类型、消息、服务端错误体（若有）、堆栈位置；以 model_call_id + attempt 关联重试 |
| 工具输入输出 | `tool_execution` 的 start / end | call_id、tool_name、完整 arguments / result、invocation_id、批准状态、原账本状态、耗时 |
| 工具内部异常 | `tool_error` / `tool_exception` | 原异常诊断与调用参数；区别于模型收到的安全错误包装 |
| 确认 / 拒绝 | `confirmation_decision` / `tool_rejected` | 决策和完整调用、拒绝结果；批准后执行有独立 invocation_id |
| 向 Agent 交付工具结果 | `tool_result_delivery` | 实际加入会话的结果；取消时区分尚未执行与已启动但可能产生副作用 |
| 独立作业输出 | `job_output` 与作业结果引用 | 用 job_id 关联状态和 stdout/stderr 的 output_refs；完整脱敏输出在独立宿主中分段保存，可通过 read_job 分页读取 |
| 消息队列 | `queue_add`、`queue_dispatch`、`queue_start` | 按 queue_id 串联入队和调度尝试。只有会话成功保存新一轮后，queue_start 才绑定对应的 run_id。 |
| 运行结论与异常 | `run_status` / `run_summary` / `run_error` / `cli_error` | 状态、完整最终回答、异常信息；包括工作区会话建立后的启动失败 |
| 恢复与取消 | `run_resume` / `run_cancel` | 恢复前状态或取消动作 |
| 本地文件更新 | `local_files_changed` | 发生变化的历史来源/产物引用、路径和失效标记；保留原哈希，不删除历史 |

一次工具调用可能先等待确认，再被批准执行，因此相同 call_id 会有多个 invocation_id。`result.pending=true` 表示等待确认，不表示执行失败；`prior_state=succeeded/failed` 可识别账本缓存返回。工具是否实际执行还应结合账本中的 executed 状态，不能仅按 start/end 事件数量推断。

`model_input` 是 Agent 交给客户端的标准消息；`provider_request` 是适配器交给 SDK 的请求参数。两层都保留，因此可检查序列化、默认参数和字段丢失。`provider_request.extra_body` 由 SDK 合并进 HTTP JSON 正文；日志不是 TLS/HTTP 字节抓包。

## 查看方法

在 GenesisAI 内执行 `/logs`。复制输出路径后，在 PowerShell 中查看最新事件：

```powershell
$appRoot = if ($env:GENESISAI_HOME) { $env:GENESISAI_HOME } else { Join-Path $env:USERPROFILE '.genesisai' }
$logPath = Join-Path $appRoot 'logs\session_实际ID.jsonl'
Get-Content -LiteralPath $logPath -Encoding UTF8 -Tail 10 -Wait
```

筛选工具输入输出：

```powershell
Get-Content -LiteralPath $logPath -Encoding UTF8 |
    ForEach-Object { $_ | ConvertFrom-Json } |
    Where-Object { $_.event -eq 'tool_execution' } |
    ConvertTo-Json -Depth 100
```

原始 JSONL 保留正文；不要使用 PowerShell 默认表格显示来判断是否丢失内容，表格本身可能截断。

## 边界

- 日志不改变模型、工具和完成判定的业务逻辑；历史问题与最新整合验收入口见[文档导航](README.md)。
- 工具自身保留分页和预览。命令结果默认读取每个输出流前 12,000 个 UTF-8 字节；完整输出通过 `read_job(job_id, output=true, offset, limit)` 或结果引用继续读取，偏移以返回值为准。作业日志按 1 MiB 分段，默认输出配额为 128 MiB；配额耗尽明确失败并保留已有输出。`jobs/limits.json` 可配置配额。
- API Key、已知认证密钥、常见密码字段和 Bearer 凭证脱敏；不记录密钥输入控件的原文。一般任务正文保留，不做通用个人信息识别。
- 工作区尚未选定、会话文件无法建立、独立 `--auth` 配置流程没有任务会话日志。会话建立后的配置/模型启动失败会记录。无法记录从未到达客户端的数据，也无法在强制结束后补写结束事件。
- 非流式模型只能在响应到达后写输出；流式模型逐 chunk 落盘。独立作业宿主持续保存捕获的子进程输出，CLI 关闭不等于作业停止；强制杀死作业宿主前尚在子进程管道中的数据不保证保存。
- `cli_output` 保存用户看到的文本（可能受终端宽度影响），完整业务正文应查看 model_output、tool_execution、run_summary。
- 不自动清理完整 JSONL，避免可用性检查证据过期；长会话会积累较大的日志文件。内存统计只保留摘要，不复制所有正文。
