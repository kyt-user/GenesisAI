# 范围授权与环境隔离

`user` 模式允许用户为一段工作预先声明范围。模型不能自行创建授权；只有用户的 CLI 命令或确认界面可以登记授权。`auto` 模式继续自动执行普通调用。数据删除及外挂能力注册验收始终需要明确确认。

## 会话和任务授权

例如，允许当前任务使用 `editor` 修改工作区的 `src` 和 `tests`：

```text
/authorize {"scope":"task","tools":["editor"],"paths":["src","tests"]}
/authorizations
/revoke auth_实际编号
```

`scope` 必须为 `task` 或 `session`。任务授权绑定当前活动任务编号，任务结束或替换后失效；会话授权只属于当前会话，恢复该会话后仍有效，不传播到新会话。授权不依赖固定分钟数过期，用户可随时显式撤销。撤销会拒绝尚未执行的相关作业并请求取消已经运行的作业；已经产生的文件或外部副作用不会自动回滚。作业结果不确定时仍保持 `unknown`，不会宣称已安全撤回。

`paths` 中的相对路径以当前工作区为基准，包含相应目录的后代。它用于判定调用参数中的资源范围；已有文件访问权限仍须满足，不会因为范围授权扩大底层文件访问权限。没有足够资源信息的调用会要求具体确认。

网页授权示例：

```text
/authorize {"scope":"session","tools":["fetch_web_content"],"domains":["example.com","*.example.org"]}
```

精确域名不包含子域名；`*.example.org` 只包含子域，不包含 `example.org` 本身。请求与每次重定向均检查域名。通用网页搜索需要访问不同来源，须具体确认或显式授予 `domains:["*"]`。`*` 不放开私网地址和 SSRF 防护。

内网读取使用独立的 `fetch_private_resource`，同时限定工具、域名及地址段，例如：

```text
/authorize {"scope":"task","tools":["fetch_private_resource"],"domains":["api.corp.example"],"address_ranges":["10.20.0.0/16"]}
```

调用声明的每个 IP/CIDR 必须落在授权地址段内；域名也可填写规范 IPv4/IPv6 地址。每次请求和重定向继续核验目标及解析结果。未覆盖的内网读取即使在 `auto` 模式也要具体确认；模型填写地址参数本身不能产生授权。内网范围不放开 metadata、link-local 等被专门拒绝的目标。公网工具不会因为存在内网授权而改变网络边界。

未覆盖的调用仍展示具体预览。单次 `/approve` 绑定参数和当前资源摘要，不因等待时间长而过期；内容、来源或映射值变化后必须重新确认。已明确授予的范围内允许后续资源更新。外挂注册仍绑定冻结版本、摘要和最新通过的测试报告，不由普通范围授权代替验收。

## 命令和环境变量

子进程默认仅继承明确列出的系统运行变量及非敏感应用配置。不会根据变量名是否包含 `KEY`、`TOKEN` 等子串来猜测是否可继承，也不会自动继承宿主的其他自定义变量。

`run_commands.env_from`、外挂 Tool 的 `definition.env_from` 和 MCP 的环境映射均使用“子进程变量名 → 宿主变量名”。MCP 的 HTTP 认证头独立使用 `headers_from`，格式为“HTTP 头名 → 宿主变量名”；头名不区分大小写，允许 `X-API-Key` 等合法 HTTP 名称，不会放松环境变量的命名规则。参数中只传名称，值从宿主环境读取。两种映射分别匹配对应授权字段；缺少来源变量会报错。运行期专用 `GENESISAI_RESULT_PATH` 不能由用户映射覆盖。

HTTP MCP 授权示例（工具名须替换为已注册的实际名称）：

```text
/authorize {"scope":"session","tools":["mcp_example_read"],"domains":["api.example.com"],"headers_from":{"X-API-Key":"MY_API_KEY"}}
```


例如，将宿主 `MY_BUILD_TOKEN` 映射为命令进程中的 `BUILD_TOKEN`：

```text
/authorize {"scope":"task","tools":["run_commands"],"paths":["."],"command_prefixes":[["python","-m","pytest"]],"env_from":{"BUILD_TOKEN":"MY_BUILD_TOKEN"}}
```

工具调用相应使用 `command:["python","-m","pytest","tests"]` 和 `env_from:{"BUILD_TOKEN":"MY_BUILD_TOKEN"}`。命令授权必须给出 `command_prefixes`，程序会按工作区解析为实际可执行文件，后续调用须匹配该程序及参数前缀。环境映射值的摘要参与单次确认；实际值经进程输入传递，并纳入日志脱敏。

命令前缀和工作目录授权不是操作系统沙箱。子进程以当前系统账号运行，代码仍可访问该账号能访问的文件和网络；不要把 `paths` 或 `domains` 理解成对任意程序的 OS 隔离。显式授予解释器、脚本或通用 shell 前缀，等同信任该前缀允许执行的代码。

## 显式任务约束

```text
/constraints
/constraints {"read_only":true,"network_forbidden":true}
/constraints {"read_only":false}
```

该命令只调整当前任务的约束，不接受 scope 参数。内部轮次约束由对应轮次的用户消息登记，保留来源及生命周期。调整某项不会改变其他项；撤销旧值并记录新值，保留来源历史。新任务不会继承旧任务的临时约束。范围授权不能绕过有效的只读或禁网约束。
