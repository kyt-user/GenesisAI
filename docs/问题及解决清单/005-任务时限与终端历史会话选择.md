# BUG-005 任务时限被档位覆盖与历史会话入口

2026-11-03 实现。对应会话 `session_58760d5c9c69447b`。

## 复现与原因

16:55:33 用户询问之前聊过什么。首次模型请求返回 HTTP 503，重试在约 105.5 秒后返回工具调用。启动配置为 300 秒，普通问答档位内部配置为 60 秒，运行器取两者较小值，返回“模型返回时已超过运行截止时间”。

该次启动创建了新会话，之前的对话需要通过 `--session` 显式加载。新增终端选择入口以便继续已有任务。

## 时间参数

- `--seconds` 控制一轮任务总执行时间，默认 300 秒。
- `--request-timeout` 控制单次模型请求超时，默认 60 秒。
- 默认值集中在 `shared/time_limits.py`。任务分类和分类切换均使用启动时设置的任务截止时间。
- 每次请求及重试重新计算剩余任务时间，摘要请求也受约束。
- 用户等待批准的时长从任务消耗中排除。
- 工具执行前检查截止时间，命令进程的 timeout 取工具配置和剩余任务时间的较小值。
- 已记录修改成功、验证成功、验证要求清零且无待执行工具时，总结请求超时会生成运行记录摘要，保存到对话并返回完成状态。验证未完成时明确显示超时和进度保存情况。

```python
task_deadline = now() + seconds

before_each_request_or_retry:
    remaining = task_deadline - now()
    if remaining <= 0:
        finish_with_saved_progress()
    request_timeout = min(configured_request_timeout, remaining)
    call_model(timeout=request_timeout)

before_command:
    command_timeout = min(tool_timeout, task_deadline - now())
    run_command(timeout=command_timeout)
```

模型请求超时参数传给 OpenAI SDK，其底层 HTTP 超时包含连接和读取阶段。流式接收逐块检查总耗时，模型返回后再次检查截止时间。SDK 的读取超时受服务端心跳影响，当前实现没有在独立进程中强制终止网络调用，因此极端网络行为下返回错误的时刻可能晚于配置时限。超过期限返回的工具调用会被拦截。

## 终端会话选择

输入 `/` 并回车，选择 `/sessions`，或直接输入 `/sessions`。

列表按最近更新时间排序，展示最近用户问题摘要、时间、会话 ID、工作区及状态。交互终端支持方向键、输入搜索、回车确认和 Esc 取消。管道输入使用序号选择，空输入取消。

```python
selected = choose(read_valid_session_files(), exclude=current_session)
if selected is None:
    return_to_current_session()

restore_saved_workspace_and_permissions(selected)
load_workspace_environment_using_process_env_priority()
rebuild_model_and_runtime()
switch_active_session_and_logger()
show_workspace_and_session_status()
```

恢复会话时使用其原工作区、授权目录、权限和历史检查点。切换工作区重新加载 ENV 和当前用户模型配置。不存在的工作区、无效授权路径与不可读取的历史文件会显示错误。取消选择保留当前会话。当前任务尚在运行或等待确认时，先处理当前任务再切换。

`--session ID` 保留为启动入口。`/resume` 用于当前会话内中断运行的恢复。加载已完成或已达到时限的会话后，可以输入新消息继续执行。

本次使用受控模型和临时目录进行离线验证。真实 API 的 thinking 历史字段问题继续记录在 BUG-004。
