# BUG-003：流式输出被动画擦除，最终判定原因未显示

[返回目录](目录.md)

日期：2026-11-03。状态：已修复并通过回归。

## 现象与证据

终端出现大量空行、零散标点及代码符号，最后只显示“部分完成”等元数据，用户无法读到完整回答或实际停止原因。

本次日志中，第 10 轮回答共有 891 个正文片段，拼接后为 1,919 个字符，与 `model_output` 的完整正文一致。提供商返回和日志记录均未丢失正文，故障发生在展示层。

另外，模型正文声称修复完成，但最终运行状态被 BUG-001 误判为 partial。最终原因保存在 `run_status` 中，界面却只显示状态栏。

## 根因

`working()` 的 Rich Status 动画包围整个模型循环；`render_progress()` 使用 `print(text, end="")` 连续写入未换行的正文。Live 动画刷新发出的回车和整行清除控制序列，会擦掉同一行上的正文。

模拟交互终端捕获到的控制顺序可概括为：

```text
显示动画
清除当前行 → 正文片段 FIRST + 动画
清除当前行 → 正文片段 SECOND + 动画  # FIRST 被擦除
清除当前行 → 正文片段 THIRD + 动画   # SECOND 被擦除
```

与此同时，旧版 `render_result()` 只检查“是否输出过流式正文”，满足时便仅打印状态栏。它没有检查最终答案是否已被运行时替换为失败解释。

## 修复方法与伪代码

流式正文开始前停止动画，并在退出工作上下文时正确清理；后续片段不再与 Live 动画竞争同一终端行。每轮记录实际输出过的正文，最终按内容是否一致决定展示方式。

```text
working():
    active_status = 创建并启动动画
    try:
        执行模型和工具循环
    finally:
        if active_status 仍存在:
            停止动画
        active_status = None

收到正文片段(text):
    if active_status 仍存在:
        停止动画  # 必须发生在写入正文之前
        active_status = None
    streaming = True
    streamed_text += text
    输出纯文本(text, 不自动换行)

开始下一模型轮次():
    如果前一轮正在流式输出，则补换行
    重置 streaming 和 streamed_text

展示最终结果(result):
    same = streaming 且 streamed_text == result.answer
    如果有流式输出，则补换行并重置流式状态
    if same:
        显示最终状态、轮次、工具和 Token
    else:
        完整显示 result.answer 及最终状态
        # 即使模型刚说“已完成”，也必须显示运行时给出的失败原因
```

实现：[app/terminal_view.py](../../src/genesisai/app/terminal_view.py) 中的 `working()`、`render_progress()`、`render_result()`；调用入口为 [app/cli.py](../../src/genesisai/app/cli.py) 的 `run_and_show()`。

## 验证与边界

- 使用强制交互终端捕获 ANSI 输出：FIRST、SECOND、THIRD 能连续保留，首段正文后不再出现整行清除序列。
- 重放真实日志全部 891 个正文片段，捕获结果与拼接后的完整回答相同。
- 先流式输出“模型声称已经完成”，再返回“测试失败，需要继续修复”，确认具体原因和 partial 状态均可见。
- 既有隐藏 reasoning 正文、HTML 作为纯文本输出等测试继续通过。

验证使用本地终端模拟和日志重放，没有重新调用真实模型 API。正确显示不能替代业务完成判定；状态漏更新由 BUG-001 单独修复。
