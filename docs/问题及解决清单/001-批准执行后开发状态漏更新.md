# BUG-001：批准执行后开发状态漏更新

[返回目录](目录.md)

日期：2026-11-03。状态：已修复并通过回归。

## 现象与复现

1. 使用默认 ASK 权限，让 Agent 修改代码、创建测试并运行测试。
2. 对编辑和命令调用分别输入 `/approve`。
3. 文件实际修改成功，测试也通过，但任务结束时显示“部分完成”。

本次日志第 158 行的 `command_output` 记录了真实执行的 `python -m unittest discover -v`：7 项测试通过，退出码 0。会话的 changes 中也存在一条代码补丁、两条测试文件创建记录。

然而最终运行状态仍为：

```text
project_changed = False
verification_succeeded = False
stop_reason = tool_required
```

日志第 1964 行给出的实际终止原因是“开发任务尚未产生项目文件变更；模型连续两次没有调用写入工具”。它与实际执行结果矛盾。

## 根因

普通工具执行路径 `_execute_pending()` 更新开发标志；等待确认的调用会提前返回。用户批准后走 `_confirm()`，该路径执行工具并交付结果，却没有更新同一套开发标志。完成判定读取了错误状态，触发了额外模型轮次并误判任务。

修复前的简化流程：

```text
普通执行(call):
    result = execute(call)
    if result 等待确认:
        return 等待用户
    append_result(call, result)
    更新项目修改和测试状态(result)

批准执行(call):
    result = execute(call, approved=True)
    append_result(call, result)
    继续模型循环()  # 缺少开发状态更新
```

## 修复方法与伪代码

把更新逻辑抽到 `_update_development_state()`，由两个执行入口共用的 `append_result()` 调用。新修改要求验证时，同时清除旧的“验证成功”标志，避免先前的测试结果覆盖后续修改。

```text
append_result(call, result):
    记录完整工具结果、消息和工具活动
    移除已处理的 pending 调用
    更新 agent_docs
    update_development_state(call, result)
    保存会话
    通知界面展示工具结果

update_development_state(call, result):
    if call 是 editor 且执行成功:
        project_changed = True
        if 工具自带验证明确通过:
            verification_succeeded = True
            verification_required = False
            needs_verification = False
        if 本次修改仍需验证:
            verification_succeeded = False
            verification_required = True
            needs_verification = True
    else if call 是 run_commands 且返回测试 summary:
        passed = result.ok 且 result.data.passed
        verification_succeeded = passed
        verification_required = not passed
        needs_verification = not passed
```

实现：[agent/loop.py](../../src/genesisai/agent/loop.py) 中的 `append_result()`、`_update_development_state()`；完成门禁：[development/policy.py](../../src/genesisai/core/development/policy.py)。

## 验证与边界

回归 `test_approved_code_change_and_tests_finish_then_allow_followup` 在临时工作区读取源码和 agent_docs，批准补丁、批准创建测试、批准真实 unittest 命令，验证项目修改标志、测试成功标志和 completed 状态，随后继续同一会话追问。

本条修复的是执行后状态同步，不代表全部完成判定问题已解决。`attempt_completion` 绕过检查、测试命令识别过宽等独立问题仍见 [审计待办](../../todo/2026-11-03-repository-audit.md)。
