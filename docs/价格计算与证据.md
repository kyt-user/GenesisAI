# 有来源的价格计算

`calculate_price` 执行确定的 Decimal 运算，并返回可引用的派生来源。它支持同币种费用合计、单价乘数量、按明确汇率方向换算；不根据模型答案中的任意算式放行价格声明。

每个操作数需要 `value` 十进制字符串、`source_ref` 和逐字原文 `quote`。金额还要提供 `currency`，汇率要提供 `from_currency` 与 `to_currency`。数值支持规范千分位和负数，不接受指数、NaN或无穷值。`decimal_places` 默认2，可设0–8；结果同时返回未舍入值、公式与ROUND_HALF_UP舍入方式。

例如用户明确提供“单价 USD 9.99，数量3件，请按这些值计算”，工具参数为：

```json
{
  "operation": "multiply",
  "operands": [
    {"type": "money", "value": "9.99", "currency": "USD", "source_ref": "user", "quote": "USD 9.99"},
    {"type": "quantity", "value": "3", "source_ref": "user", "quote": "数量3件"}
  ],
  "decimal_places": 2
}
```

结果为USD29.97，最终回答须说明“基于用户给定前提”，并引用工具返回的 `source_ref`。用户给定前提不是已经核实的市场报价。`user` 只匹配当前用户原消息，并绑定消息正文哈希；模型补写的quote不会被接受。

外部价格使用当前会话已读取的 `src_` 来源，quote必须逐字存在、币种和金额相符。网页正文验证保存哈希；本地文件验证当前授权、文件哈希与文字。文件变化或授权收紧后，依赖它的计算不能继续支持答案。

`sum` 只合计同币种金额；跨币种请先 `convert`。汇率quote需要明确方向，例如 `1 USD = 7.2 CNY`，不能仅提供数字7.2。数量quote需要明确数量或单位，不能把编号、年份等任意数字作为系数。

计算结果可作为下一次计算的金额来源。派生引用重验上游依赖与实际运算，并保留原会话归属；另一会话需要重新读取授权来源并计算。来源本身的时效性、产品和地区适用性仍需核对，计算结果不自动获得“当前市场报价”的身份。
