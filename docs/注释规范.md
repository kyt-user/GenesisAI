# GenesisAI 注释规范

> 适用于 `src/genesisai/` 全部 Python 源码。

---

## 一、语言

- **统一使用中文**书写所有注释和文档字符串。
- 技术标识符保持原样：类名、函数名、参数名、库名、错误码等不翻译。
- 示例：`ToolError("permission_denied", "路径超出授权范围")` 中的错误码保留英文，描述用中文。

---

## 二、模块级 docstring

每个 `.py` 文件顶部必须有模块 docstring，一句话说明本模块职责。

```python
"""工具目录查询和 Core、Active、Available、Disabled 四层状态管理。"""
```

- 不超过两行。
- 如果模块只有一个主类，docstring 可以只写该类的职责。

---

## 三、类 docstring

公开类必须有 docstring，说明用途和关键约束。

```python
class Runner:
    """可持久化的单智能体 ReAct 循环。

    研究和完成策略由独立确定性模块约束；
    工具调用通过 ToolRuntime 执行，结果写回会话存储。
    """
```

- 内部辅助类（以下划线开头）可省略。
- 数据类（dataclass）如果字段名已自解释，可省略。

---

## 四、函数 / 方法 docstring

### 必须写 docstring 的情况

| 场景 | 示例 |
|------|------|
| 公开 API（模块级函数、类的公开方法） | `def chat(...)`, `def read(...)` |
| 逻辑复杂、函数体超过 15 行 | `def drive(...)`, `def _recover_tool_required(...)` |
| 副作用或安全相关 | `def atomic_json(...)`, `def safe_name(...)` |

### 可以省略的情况

| 场景 | 示例 |
|------|------|
| 私有方法且函数名已自解释 | `def _disabled_reason(...)` |
| 属性访问器 / 简单 getter | `def active_names(...)` |
| 协议接口方法，由基类 docstring 覆盖 | `def prepare(...)`, `def execute(...)` |

### 格式

```python
def drive(self, request: str, *, recovery: bool = False) -> str:
    """执行一轮完整的 ReAct 循环。

    按 思考→行动→观察 迭代，直到产出最终回答或触发限制。
    返回最终回答文本；异常由调用方捕获。
    """
```

- 第一行：做什么（一句话）。
- 后续行：关键约束、返回值、异常（仅在必要时）。
- 参数说明优先用类型注解，不在 docstring 里重复 `:param:` 列表。

## 五、行内注释

### 何时写

| 必须写 | 不写 |
|--------|------|
| 非显而易见的业务规则 | 代码本身已能说明的操作 |
| 安全/权限决策点 | 简单的赋值、返回 |
| 正则表达式的意图 | 标准库调用的逐行解释 |
| 与直觉不符的 workaround | |
| 分段的长函数内部逻辑块 | |

### 格式

```python
# 源码文件不能附加来源引用；报告文件才需要。
is_source = suffix in SOURCE_SUFFIXES
if is_source and refs:
    raise ToolError("invalid_source", "源码文件不能附加报告来源")
```

- 注释写在代码**上方**，不要写在行尾（除非是变量单位的简短标注）。
- 使用完整句子，首字大写，句末加句号（中文句号 `。`）。

## 六、常量与配置

```python
# 报告类文件：允许附加来源引用。
REPORT_SUFFIXES = frozenset({".md", ".txt", ".csv", ".json"})

# 源码类文件：禁止附加来源引用。
SOURCE_SUFFIXES = frozenset({".py", ".java", ".html", ...})
```

- 业务相关常量组必须注释说明用途和约束。
- 纯技术常量（正则、编码名）可省略注释。

---

## 七、TODO 与 FIXME

```python
# TODO(kyt44): Windows 下 os.replace() 文件锁问题需要改用 shutil.move。
# FIXME: 深思考模型的 reasoning_content 字段在部分版本中缺失。
```

- 格式：`TODO(作者): 描述` 或 `FIXME: 描述`。
- 必须足够具体，能直接定位修复方向。

---

## 八、禁止事项

1. **不要**用注释复述代码逻辑（`# 把 x 加 1` → `x += 1`）。
2. **不要**保留被注释掉的旧代码——用 Git 追溯。
3. **不要**在注释中包含密码、Token、内部 URL。
4. **不要**混用中英文写同一个注释段落。

---

## 九、现有代码整改优先级

| 优先级 | 范围 | 说明 |
|:---:|------|------|
| P0 | 核心循环 `agent/runner.py` | 15 个方法仅 3 个有 docstring |
| P0 | 提示词组装 `prompt/composer.py` + `context_budgeter.py` | 英文 docstring 需改中文 |
| P1 | 工具运行时 `runtime/*.py` | 部分函数缺 docstring |
| P1 | 能力工具 `capabilities/*/implementation.py` | 多数无模块 docstring |
| P2 | 数据定义 `shared/*.py` | 少量函数缺注释 |
| P2 | 评测 `evals/*.py` | 英文 docstring 需改中文 |

整改时遵循本规范，**不改变任何业务逻辑**。
