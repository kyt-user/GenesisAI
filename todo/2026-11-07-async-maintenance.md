# F04/F09 与通用异步执行实施记录

本记录属于 149 项限制改造的阶段证据，全量回归、最终审计及 Git/GitHub 提交尚未完成。

## 已实现

- F04：项目 Git 枚举使用可取消进程、可选总时限及明确缓存新鲜度。`index.json` 提供 Git 时限、目录排除、缓存 TTL 和进度批量配置。显式重建跳过缓存；解析器更换以版本保存下一次重建需求。
- F09：持久队列独立于模型轮次排空，共享全局作业槽位及维护池；支持状态、分页、进度、等待和取消。当前文件变更同步使来源与知识失效，后台扫描用 dirty revision 防止旧扫描覆盖新修改。
- 取消通过持久文件信号和独立观察线程传达，不等待 SQLite writer，也不依赖处理器再次发进度。数据库打开现有结构先只读检查，状态读取不先占写锁。
- 每个后台调度生命周期持有独立停止信号。关闭期间新提交不会清除旧执行的中断意图；中断的派生工作重排后再启动下一代线程。明确取消不恢复执行。
- E01：文件工具可声明 `execution='job'`，使用独立持久作业；准备/审批和后台执行分别计时。已有 Office、`read_files`、`list_files` 接入；真实 OCR 接缝由文档子任务验证。文件工具获得受控 Access、来源/产物/修改暂存、日志及冻结分页预算，宿主服务仍需专门适配器。
- 结果收取按当前授权范围复核，将暂存效果与作业 receipt 一起提交；原会话其间的新状态保留。收取绑定 call_id，重复读取不再次产生修改观察，中断收取可由新调用接管。历史来源缺失时保留结果并标 stale。
- 作业取消先向所有目标发信号，再共享一次等待窗口，避免按作业数量累加等待。unknown 作业也能留下停止请求；结果发布失败不能把已发生副作用降格成可自动重试的普通失败。
